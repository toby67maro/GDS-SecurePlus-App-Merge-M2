# 4.0.0-beta.2 test checklist

Upgrade a 4.0.0-beta.1 test database (or start fresh). Use a test tenant with a Global Administrator.

1. **Install / upgrade**: the database reaches V0012; the catalogue shows 3,333 controls (Catalog page) including 195 `TS-` tenant settings.
   Tick *Install PowerShell modules*: PowerShell 7, ExchangeOnlineManagement 3.10.1 and MicrosoftTeams 8.0.0 are installed (`Get-Module -ListAvailable` in pwsh).
2. **New customer > Connect tenant**: sign in as Global Administrator; the job shows every step; *GDS Secure Plus Read* exists in Entra with
   read-only Graph permissions, Exchange.ManageAsApp (Exchange Online and Exchange Online Protection), the Global Reader role and one certificate,
   no client secret; a quick scan starts. *Skip – connect later* closes the card.
3. **Upgrade an existing tenant**: Customer Profiles > Tenant Access > *Update Read Access*: the old *Agent* app is renamed, its write permissions
   and client secret are removed, the credential shows *Certificate*. Test Connection passes.
4. **Quick scan / in-depth scan** (Assessment Scan and Live Assessment): quick scan fills Tenant Users and Groups and the Entra group pickers;
   in-depth scan adds Exchange (`exo:`), Purview (`scc:`) and Teams (`teams:`) results. Without the modules those show *not collected* with the install command.
5. **Tenant settings**: results per area; a setting needing an unlicensed feature shows *Info: not applicable* and is not in the score; manual settings show their click path.
6. **Policies and Policy Sets** (Settings): create a Lead policy, edit a GDS policy (shows *GDS (edited)*), hide it, revert; restart the app (the GDS
   catalogue is synced on start) and check the edits remain; edits made in beta.2 also survive the next upgrade; history cannot be edited (SQL: UPDATE/DELETE denied).
7. **Conditional Access rules**: removing the break-glass exclusion in the editor is refused; a Staged CA task cannot be completed before 14 days.
8. **Deployment access**: Change Execution > Apply to Tenant without deployment access shows how to enable it. *Enable Deployment Access* creates
   *GDS Secure Plus Deploy* (write permissions only, certificate). Apply a test change (passcode); policies are created report-only.
   *Remove Deployment Access* deletes the app from Entra and the certificate from Credential Management.
9. **Secrets**: exports, logs and the audit ledger never contain a certificate, private key or client secret (search an export for `pfx:`).
10. **QR code + PIN**: available as an MFA method option only by choice; the SOW says it is not MFA; CA-213/CA-214 use `FrontlineQrCodeGroup`.
11. **Regression**: full automated suite on SQL Server 2022; smoke test of each menu.
