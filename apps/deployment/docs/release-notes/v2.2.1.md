**Secure Plus – Modern Work 2.2.1.** Fixes the knowledge base load on SQL Server and the problems found in the 2026-11-07 application log. Published as a pre-release because the build is not code-signed.

### Downloads
- `GDS-SecurePlusAgent-2.2.1-win-x64-Setup.exe` – installer (recommended). Upgrades 2.x; no schema change.
- `...-portable.zip`, `...-framework-dependent.zip` – engineering builds.
- `...-SHA256SUMS.txt` – SHA-256 checksums of every download.

### After Upgrading
- No database rebuild is needed. The knowledge base loads in the background when 2.2.1 starts; the activity panel shows **Load the knowledge base**. On SQL Server the first load takes about 2 minutes (measured on a 4-core SQL Server 2022); **Reload Knowledge Base** takes up to about 4 minutes.
- In **Tenant App Registration**, select **Update Permissions Automatically** once per customer tenant to grant the new `DeviceManagementScripts.Read.All` permission.

### Fixed
- **Knowledge base on SQL Server.** 2.2.0 stopped with *Cannot insert duplicate key row in object 'fw.Requirement' with unique index 'UX_Requirement_NaturalKey' … (…, 19(3)(c)(i))*. The SCF workbook lists four Hong Kong PDO requirements twice in different letter case; SQL Server treats them as the same code. They are now merged (44,258 requirements, 76,019 mappings), and the loader compares codes the way SQL Server does on every database. Tested on SQL Server 2022 (load and reload).
- **First-run setup.** Create Database, Install or Repair and other buttons that ask for confirmation failed with *Cannot set Owner property to a Window that has not been shown previously*.
- **Audit file locked.** Opening **Auditing and Logs** could stop audit events from being written (*…audit-yyyyMMdd.jsonl because it is being used by another process*).
- **Assessments.** Intune settings catalog and endpoint security policies, and assigned apps, are now read (they exist only in the Graph beta API); Intune PowerShell scripts are read once the new permission is granted.
- **Create Database** on a server that still has `SecurePlus.mdf` / `SecurePlus_log.ldf` from a removed database now says to attach the files again, or move or delete them.

### Known Issues
- `sensitivityLabels` (HTTP 400) and `retentionLabels` (HTTP 500 *Forbidden*) are reported as not available for some tenants by Microsoft Graph; the assessment marks those checks as not collected.
- Tenant client secrets created before an organization key exists are kept on that computer; create the key in **Settings > Credential Management** so they move into the database.
- No writes to customer tenants. Unsigned build: SmartScreen may warn.
