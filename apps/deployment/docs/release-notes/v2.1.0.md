**Secure Plus – Modern Work 2.1.0.** The SecurePlus database is now the system of record: customers, workspaces, settings, themes and tenant secrets are shared by every computer that connects to it. Published as a pre-release because the build is not code-signed.

### Downloads
- `GDS-SecurePlusAgent-2.1.0-win-x64-Setup.exe` – installer (recommended). Upgrades 2.0; on first start each computer moves its local customers, workspaces and settings into the database and keeps the old files in `%LOCALAPPDATA%\Global Data Systems\Secure Plus Agent\data\Backup`.
- `...-portable.zip`, `...-framework-dependent.zip` – engineering builds.
- `...-SHA256SUMS.txt` – SHA-256 checksums of every download.

### Upgrade Steps (Do This First)
1. Install 2.1.0 on **one** computer first and start it. It upgrades the database to schema 7 and imports that computer's data.
2. Go to **Settings > Credential Management** and select **Create Organization Key**. Copy the key into your password manager. Tenant client secrets on this computer move into the database (encrypted) the first time each customer is used.
3. Install 2.1.0 on the other computers. On each, enter the organization key on **Credential Management** (or in setup) so it can use the shared tenant connections.
4. Open **Settings > Database Health > Data Coverage** (or run `scripts/sql/Audit-SecurePlusDatabase.sql`) to see which tables are filled.

### Main Interface
- Switching the workspace at the top of the window switches to that workspace's theme.
- An orange **TEST DATABASE** banner is shown when the database is a Test database.

### Workspace
- **Customer Profiles**: New Customer form; Organization section (industry as a 2022 NAICS sector, organization size, address, city, state/region, postal code, country, main phone, e-mail, website, CRM account ID); GDS Team section (sales lead, technical lead / assigned engineer, project manager, service tier, change approvers); Contacts editor (name, title, role, e-mail, phone, mobile, primary contact, approves changes, decision owner). Everything is validated and written to `cust.Customer`, `cust.Contact` and `cust.Engagement`.

### Settings
- **Workspace Configuration**: Workspaces (New, Edit, Open, Archive; customer and theme per workspace); Themes (New Theme from a few colours, Preview, Make Default, Delete); Settings listed by category and name in plain language, showing whether they apply to all computers or this computer and who changed them last. No file names are shown.
- **Credential Management**: Organization Key (create, enter, show for another computer, copy, save to file).
- **Application Settings**: the Environment setting is replaced by the database mode.

### Database
- Schema V0007: `secureplus.Setting`, `DatabaseProperty`, `Theme`, `CustomerProfile`, `TenantSecret`, `ClientInstall`; address and contact columns on `cust.Customer` and `cust.Contact`; connection columns on `cust.Tenant`; link columns on `cust.Exception` and `deploy.ChangeRequest` (differences from EaaS v3 are logged in `docs/DECISIONS.md`).
- First-run setup asks **Production or Test** and stores it in the database. Production: schema upgrades need a confirmation, no sample data. Test: sample data allowed, upgrades applied automatically, TEST banner.
- Now filled: `cust.Customer` (all columns), `cust.Contact`, `cust.Tenant`, `cust.Engagement` (leads, service tier, primary tenant), `cust.TenantLicense` and `kb.LicenseSku` (licences from every assessment), `audit.TenantConnection` (app registration, consent, last verification), `cust.Exception` (approved exceptions), `deploy.ChangeRequest`, `sec.AppUser`, `secureplus.ClientInstall`.
- Seeded: `ref.CodeSet`/`ref.CodeValue` (NAICS sectors, organization sizes, contact roles, cloud environments, engagement status and type, exception types), `ref.ImplementationStatus`, `ref.MaturityLevel`, `ref.RelationshipType`, `ref.EntityType`, `svc.ServiceTier`, `sec.AppRole`, `eux.ExperienceArea`.
- **Database Health > Data Coverage**: rows in every table, who fills it, and the tables that need attention; export to .csv, .html, .json, .txt.

### Known Issues
- Tables of the EaaS knowledge base (SCF, NIST, CIS, MITRE, Microsoft baseline content) and of other EaaS components (delivery estimating, SOW, rate cards, questionnaires, drift, ConnectWise PSA) stay empty: they are loaded by those components. See `docs/DATA_COVERAGE.md`.
- `Database.ini` stays on each computer: it tells the application where the database is.
- A computer without the organization key cannot use tenant connections stored by others until the key is entered.
- No writes to customer tenants (unchanged from 2.0). Unsigned build: SmartScreen may warn.
