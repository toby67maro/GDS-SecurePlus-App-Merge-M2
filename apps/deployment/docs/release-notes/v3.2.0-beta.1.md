**Secure Plus – Modern Work 3.2.0-beta.1.** First step of the approved blueprint: one shared SQL Server, Server and Workstation installs, per-user roles, an audit log nobody can alter, and a scheduling computer. A test build: install it on test computers against a test SQL Server, not your production database.

### Downloads
- `GDS-SecurePlusAgent-3.2.0-beta.1-win-x64-Setup.exe` – installer. The first page asks **Workstation**, **Server** or **All-in-one**, then the SQL Server.
- `...-portable.zip`, `...-framework-dependent.zip` – engineering builds.
- `...-SHA256SUMS.txt` – SHA-256 checksums.

### Install
1. Run the installer once as **Server** (needs permission to create databases on the SQL Server). It creates the database, upgrades it and loads the reference catalog.
2. Install everyone else as **Workstation** with the same SQL Server. Silent: `/VERYSILENT /TYPE=Workstation /SERVER=sql01.gds.local`.
3. Upgrade the Server install first, then workstations. Full guide: `docs/SERVER_INSTALL.md`.

### New
- **Settings > Users & Roles**: add yourself first as **Lead**, then each person by Windows account (`GDS\name`) with one role. **Grant Database Access** creates their SQL Server login and role, or gives you the script for your DBA. Until the first user is added, everyone has full access as in 3.1.
- Only Engineers, Technicians/Deployers and Leads can use tenant credentials and hold the organization key; the database enforces it.
- **Audit ledger**: every audit event, credential use, approval and deployment is also stored in an append-only SQL Server 2022 ledger table that nobody can change or delete.
- **Settings > Database Health > Scheduling Computer**: choose the one PC that runs recurring assessments; Database Health warns when it stops checking in.
- **Move to SQL Server** (Database Configuration, when a computer still uses SQLite): copies everything, checks every table's row count, and never changes the SQLite file.

### Test
Follow `docs/testing/3.2.0-beta.1-checklist.md`; every item must pass before beta.2 (staff sign-in with Entra ID) starts.

### Known Issues
- Staff sign-in with Entra ID, step-up MFA and menus by role arrive in beta.2; the Advanced Mode passcode still protects live changes.
- Roles are enforced by the database once people connect with their own Windows logins (Grant Database Access); a shared SQL login bypasses them.
- Unsigned build: SmartScreen may warn.
