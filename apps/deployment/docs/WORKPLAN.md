### Assessment results today

`AssessmentService.RunAsync` (Application) runs as a background job: collects Graph datasets, evaluates the catalog
in memory, then writes **everything in one call at the end** (`CompleteAssessmentAsync` → `secureplus.AssessmentStatus`
+ `secureplus.AssessmentResult`; header also in `cust.AssessmentRun`). A failure marks the run Failed with a single
`ERROR` row; cancellation sets it back to Pending. Nothing is written to `cust.Finding` / `cust.RequirementResult`.
**Live Assessment does not persist anything** (in-memory only, by design in v1.3.0). Schedules
(`secureplus.AssessmentSchedule`) run only while the app is open (1-minute `PeriodicTimer`), daily/weekly/monthly
only, one day of week/month.

### Duplicate catalogue IDs

31 controls carry a `-2` suffix (`CA-203-2`, `ES-1011-2`, `ES-1013-2`, `ES-1014-2`, `ES-1300-2`…`ES-1318-2`,
`ES-1350-2`, `ES-1501-2`…`ES-1504-2`, `ES-1619-2`, `ES-1639-2`, `ES-1659-2`). Cause: the source policy repository
contains **two files with the same policy number** for the same setting with a different value (e.g. ASR rules
`Audit` vs `Block`, Network Protection `Audit Mode` vs `Block Mode`, cloud block level `Default` vs `High`); the
generator de-duplicates IDs by appending `-2`. **None is an identical copy**: each has its own Graph body and value.
The base ID is the one referenced by the policy sets (Golden Tenant etc.); the `-2` variant is in no policy set.
`CA-203-2` is a different CA policy (internal users only, guests not excluded).
